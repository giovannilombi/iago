# IAGO — Shared projects through a cloud folder

Draft design for phase 4, to be discussed. October 2026.

## In one sentence
A shared project lives in a **cloud folder the group already has**: a company OneDrive or SharePoint, but also Google Drive, Dropbox or iCloud Drive. Anyone with access to the folder uses it in IAGO as if it were their own.

IAGO has no server and makes no network connections: the cloud folder's app does.

## What the user sees
- In a project's menu: **Share in a space…**. You choose the cloud folder, for example `OneDrive - Azienda/IAGO/Marketing`.
- Next to the project the **cloud folder icon** appears, just as the Claude logo appears today for projects Claude can read.
- **From that moment the project is no longer "mine".** It belongs to the space: anyone with access to the folder sees it, records in it, transcribes, adds notes and key points, generates summaries. Each piece of content carries the name of whoever created it.
- **Whoever opens the folder outside IAGO** (from the Finder, from the OneDrive website, from Teams) finds the materials **readable**: summaries, transcripts, notes and key points in Markdown, and the audio.
- **Projects that aren't shared stay on the Mac, as today.**

## How the folder is made
```
Marketing/                          the "space"
  Portale clienti/                  readable by people
    2026-10-21 Kickoff con Acme.md  summary, key points and transcript
    2026-10-21 Kickoff con Acme.m4a
    Note/…  Punti chiave.md
  .iago/                            reserved for IAGO
    spazio.json                     name, rules, owner
    membri.json                     who takes part and who is admin (signed)
    dispositivi/<id>/modifiche/…    each Mac's log, append-only
    dispositivi/<id>/istantanee/…   the compact state, every now and then
    asset/<impronta>                original transcripts and documents
```

- **Each Mac writes only in its own `dispositivi/<id>` subfolder.** Two people never write the same file at the same time, so the cloud folder doesn't create conflicted copies.
- **No shared database.** A SQLite archive in a synced folder gets corrupted. Each Mac keeps its own archive and reads the others' logs.
- **Conflicts:** if two people change the same field, the last change wins, with a logical clock that doesn't depend on the Macs' time. For texts (notes, summaries edited by hand) both versions are kept and IAGO flags it.
- **Deletions:** they are "tombstones" that each Mac applies, not files that disappear.
- **The readable files** (Markdown and audio) are regenerated by IAGO from the log: they are a view, not the source. If someone edits them by hand in OneDrive, IAGO doesn't use them as a source; at most it flags the difference.

## Access and confidentiality
- **Whoever has access to the cloud folder decides.** Sharing the folder with a colleague means giving them access to the project in IAGO. Removing it means removing it.
- In a protected company area encryption isn't needed: the materials are deliberately readable.
- An encryption option per space (of the audio, or of everything) remains possible for those who use less protected folders.

## Administration (admin) without depending on a company or on OneDrive
IAGO will also be distributed outside the company, so administration can't rely on a OneDrive administrator or on a company directory. Proposal: administration is a role of the **space**, not of the company.

- **Whoever creates a space is its owner.** They can appoint other admins and transfer ownership.
- **Each user has their own signing key**, created by IAGO and kept in the Keychain.
  - `membri.json` (who is admin) is signed by the owner.
  - Administrative actions are signed by an admin: delete for everyone, archive the project, exclude a member from the space, change the rules (audio yes/no, encryption).
  - The other Macs apply only actions signed by a valid admin. A `membri.json` file tampered with by hand, or an unsigned "deletion", is rejected.
- **It works with any cloud folder**, because the trust lies in the signatures inside the folder and not in the service that hosts it.
- **Honest limit:** whoever has write access to the folder can still delete files with the Finder or from the OneDrive website. IAGO can't prevent it.
  - Each Mac keeps its own complete copy, so nothing is lost and IAGO can republish.
  - IAGO notices missing or altered files and flags it.
  - OneDrive has version history and a recycle bin.

## What stays personal
- Projects that aren't shared.
- Settings and the connections with Claude.
- "Ask IAGO" conversations, unless they are saved as a note.
- Recordings made in a shared project become the space's when they are saved. Before that, it's still possible to discard them.

## Process rules, outside the app
Decided at the review board of 2026-11-02 (ADR-0082, ADR-0083). They are written into the company's processes, not implemented, so the app doesn't become less standard:
- **Client projects are shared from day one**, so whoever inherits them (a manager of a PM who leaves the company, for example) loses nothing. The data of shared projects belongs to the company.
- **The lead's deputy** is chosen by the main PM, as part of managing the project: the app has no hierarchy and doesn't model it. In the app there is only the lead, whose choice wins in a conflict (ADR-0082).

## Space used
- Texts: a few MB per project.
- Audio: about 30 MB per hour of call. Per space you choose "audio too" or "text only"; with OneDrive the audio can be kept "online-only" and downloaded on demand.

## In several phases
1. **Shared spaces and projects, text only:** log, conflicts, icon, readable files.
2. **Audio** in the space.
3. **Administration:** owner, admins, signed actions.
4. **Tests with other cloud folders** (Google Drive, Dropbox, iCloud) and optional encryption.

## Questions for discussion
1. One space per department, one per client, or free?
2. Audio in the space by default, or only the texts?
3. Is administration needed from the first version, or is the owner enough?
4. How acceptable is it for the cloud folder to take a few minutes to propagate a change?
